# A scoped token opens one repository

**Status:** proposed (2026-11-11). Revises the "Authorization, today" paragraph of the walgit README ("one trust boundary: any HTTP token can read and write any repository") without removing it: the admin token keeps exactly that reach. Builds on [ADR-0010](./0010-walgit-shared-kernel.md) (the verifier is Shared Kernel code, run by both halves) and [ADR-0008](./0008-walgit-runs-on-a-cloudflare-container-without-ssh.md) (the edge is a Worker in front of a Container, and a cold start is the cost to avoid). Leaves [ADR-0012](./0012-a-name-can-refuse-a-stranger.md) and [ADR-0013](./0013-a-name-can-refuse-a-stranger-reading.md) untouched: Signer Lists and Reader Lists are judged on top of this, exactly as before.

walgit accepts a **Scoped Token**: a compact JWT, signed with Ed25519 (`alg: EdDSA`), that grants `read` or `write` on **exactly one repository**, for a short time. An issuer — the first is Fredrin, hosting git for people with no GitHub account — holds the private key and mints one per repository it hands out. walgit holds only the public key, in `WALGIT_TOKEN_PUBLIC_KEYS`. With that variable unset, nothing about walgit changes.

## Why

Until now walgit had one credential, `WALGIT_HTTP_TOKENS`, and every holder of it could read and write every repository. That is the right shape for one operator and the wrong one for a host serving many tenants: handing a tenant the token hands them every other tenant's code, and the alternative — a proxy in front that rewrites credentials — is a second service to run, scale and keep correct. The request (GitHub issue Zabaca/zbc#205) was for walgit to authenticate tenants itself.

## What was decided

- **The format is a standard one.** A compact JWT, `alg: EdDSA` over Ed25519, so an issuer signs with the library it already has. Exactly one algorithm is accepted; `none`, any HMAC (the public key used as a shared secret is the classic confusion), RSA and ECDSA are refused, as is a header naming `crit` extensions.
- **walgit holds only the public key.** A compromised walgit can refuse tokens and accept them; it can never mint one. `WALGIT_TOKEN_PUBLIC_KEYS` is comma-separated, so a signing key rotates the way `WALGIT_HTTP_TOKENS` does: add the new key, move the issuer, drop the old one. Each entry is the key's 32 raw bytes in base64url — the `x` of its JWK, and what `walgit token keygen` / `walgit token public-key` print.
- **One repository per token, by exact name.** The `repo` claim is a repository id compared for equality, never a prefix, a pattern or a namespace. Prefix grants were considered and refused: repository names here are flat and first-come, so a prefix is not a boundary anyone owns, and one wildcard bug would be every tenant's data. An issuer wanting two repositories mints two tokens.
- **`mode` is `read` or `write`.** A `read` token reaches every read surface of its repository and is refused (403) at `git-receive-pack`, including the advertisement a push begins with, so git stops before sending a pack.
- **A `write` token may create its repository on first push**, exactly as an admin token can today. It cannot name any other, so creation is no wider than the grant.
- **`exp` and `iat` are required, with a fixed 60-second skew.** A token is honoured until `exp` plus the skew, and one whose `iat` is further in the future than the skew is refused. `iat` is required now, though nothing yet reads it beyond that check, because revocation will be built on it: a per-repository "tokens valid since" instant in the Index refuses every token issued before it, with no list of revoked tokens to store. `sub` (the tenant) is optional; when present, the per-source rate limits count a push in a bucket for that `sub` rather than for the address it came from. `nbf` is optional too and honoured when present. There is no `aud`: the boundary between deployments is the key — **an issuer uses a separate keypair per deployment**, so a token minted for `my-thing` on one host does not verify on another that has a repository of the same name. walgit sets no maximum lifetime; how long a token lives is the issuer's decision, and with no revocation yet it should be short.
- **It travels where tokens already travel.** The Basic-auth password (`git clone https://walgit:$TOKEN@host/repo.git`) or `Authorization: Bearer`, read by the same `presentedCredential` every other credential is read by. A credential is judged as a scoped token only when the keys are configured, it has a JWT's shape, and it is not one of the deployment's own secrets — so an admin token keeps its full reach whatever it looks like, and a Read Challenge signature (which contains a colon) is never mistaken for one.
- **Verified at the edge, before the container wakes, and again in the container.** The verifier is WebCrypto in `shared/scoped-token.ts`. The edge Worker runs it first on every request, so a bad or out-of-scope credential costs no cold start; the container runs the same function on what reaches it, so the rule holds for a request that did not come through the edge.
- **Valid only for its repository, on every surface.** Smart HTTP, the web view's pages and raw files, the Provenance Read, Proposals, the event stream (judged on the `watch` message, which is where repositories are named, and closed once the token expires), every MCP tool call, and the repository list, which shows the token its own repository and nothing else — not even a count. Presented anywhere else it is refused with 403, **even where an anonymous request would be served**: a client wanting the anonymous view sends no credential, and a token that quietly downgraded to anonymous would hide a misrouted credential.
- **401 versus 403.** A token that does not verify — expired, badly signed, signed by an unconfigured key, malformed, the wrong `alg` — is 401 with the usual Basic challenge. A token that verifies and asks for something outside its grant is 403. A malformed `WALGIT_TOKEN_PUBLIC_KEYS` refuses scoped tokens (503, naming the entry) and leaves the admin credential working.

## Consequences

- The admin credential is unchanged and is still the only way to administer. The token rules are additive: Private repositories, Reader Lists, Signer Lists, signed pushes and the per-source rate limits all apply on top. A scoped token cannot open a Private repository: the token and a Read Challenge signature both travel in the one `Authorization` header, so a request carries one or the other, and a Private repository answers only the signature. Hosting private repositories for tenants with scoped tokens alone would need a later decision about which wins.
- A token cannot be revoked before `exp` yet. Issuers should keep lifetimes short; the revocation built on `iat` is the next step, not this one.
- An event-stream subscription is judged when the `watch` message arrives, and the socket carries the token's `exp`: the first ref event after it expires closes the socket instead of being delivered. Revocation will have to re-judge open sockets too, as a Reader List change already does.
- The MCP endpoint's `manual` resource is `/llms.txt`, a public document; a scoped token can read it there although `/llms.txt` itself refuses one. It names no repository.
- The edge now runs one signature verification per request that presents a JWT-shaped credential. Requests without one pay a regex.
