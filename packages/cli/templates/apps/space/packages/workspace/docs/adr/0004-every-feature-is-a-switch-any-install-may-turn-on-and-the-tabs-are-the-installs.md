# Every feature is a switch any install may turn on, and the tabs are the install's

Status: accepted. Amends the company layer's earlier line, in this package's `CONTEXT.md`, that the space has "the same seven tabs in every install", and removes the operator check that the layer's first declaration had.

## What changed, and why

The declaration (`src/declaration.ts`) used to say which company was the operator's own (`company.own`, accepted only for the operator's company by a constant, `OPERATOR`) and refuse eight of its nine switches to anyone else (a constant list). The guard was real: another company's file could not turn on the operator's Gmail by a typo or by claiming to be the operator. But it made the features one company's, not the code's, and the parts mostly did not read the switches at all (only Claude's script was read; the rest were checked in the declaration and never enforced), so another company's install would have run meet's calls and the phone's screens whatever its switches said. The space is meant to be installed by other companies, so no feature may be a company's alone.

## The rule

1. **No operator, no operator-only switch.** `company.own`, `OPERATOR` and the list of eight switches are gone. Any install may turn any switch on. A declaration that still says `company.own` is refused as an unknown field.
2. **A switch is allowed exactly where the settings it needs are declared.** The guard that `own` gave is kept by requiring each feature's own settings: Gmail needs its push host and an install's own Google app (client id and push topic); the mail server's mailbox needs at least one declared mailbox (address, name, door, the name of the secret that holds its key); the phone needs its phone list (who has the dial pad, and the number each one's 911 calls leave from); Claude's script, the Telegram bridge and a source of Clients each need their door (path and service token); the assistant needs a business mailbox to draft for; calls and many-clients need nothing. A switch on without them is a declaration that does not parse, so a half-set-up feature fails at deploy and is never found broken later; a setting present with its switch off is refused too, so a declaration says exactly what it runs. An existing install's declaration gained exactly the settings it already ran with and nothing else; the values are the deployed ones, pinned equal to the deploy's by the infra package's tests.
3. **Every part reads its switch** (`Install.has`), so the rule is not only the declaration's. Meet makes no call and answers none of the call API where `calls` is off, and has no phone (no Telnyx, no dial pad, no Phone conversation, no webhook) where `phone` is off. The inbox has no Google to sign in to, no mail-server mailbox, no model for the assistant and no Telegram bridge where its switch is off, and no spam check on arrival where no mailbox has spam questions. *(Amended by ADR 0006: the spam check is per mailbox and no longer reads the `assistant` switch; as first written here it depended on that switch, which was a mistake of framing and is undone.)* The space's Worker answers a path whose switch is off (the calendar's and Gmail's connection, the phone's, a call's) as a path that is not there before any part is asked, has no push host where `gmail` is off, and tells the page its switches (`/api/me`) so it draws no call button, phone, Calendars or Gmail section the install does not have.
4. **The tabs are the install's.** `Install.tabs` is `TABS` in their fixed order less the tabs whose part is off: **Calendar only where `gmail` is on** (a space with no Google account has no Calendar tab) and **Inbox only where the install has a mailbox of any kind** (Gmail, a mailbox on its mail server, Telegram, or a business mailbox it declares). Today, Meet, Forms, People and Knowledge are every install's. A tab that is not there is not found at its address. An install with every switch on has all seven, in the order they always had.

## What this gives and costs

- **Gives:** a second install is a declaration, not code; a company that says nothing gets Today, Meet, Forms, People and Knowledge and nothing that cannot work for it (no Calendar it cannot connect, no Inbox with nothing in it).
- **Costs:** a feature's settings are declaration content, so each is validated by `parseDeclaration`. A copy of a value the deploy also holds was pinned by a test until the install kit (ADR 0007) wrote the Worker's settings from the declaration. It does now: the Worker's `INBOX_JMAP_MAILBOXES` var and the Gmail vars are the kit's output (the infra package's `test/jmap-door.test.ts` and `inbox-google-vars.test.ts` still pin them to the mail server's door and Google's module).
- **Left for later:** the phone's caller name and greetings are constants of meet's phone line (see ADR 0005), so the phone is in practice one install's; making them the install's waits for a second install that has a phone. The personas and spam questions are the install's content (ADR 0006).
- **Not changed:** when this was decided the inbox admitted one owner and no member; the inbox's ADR 0004 later gave mailboxes people. The sign-in check and trust model (ADRs 0001 to 0003) are as they were.
